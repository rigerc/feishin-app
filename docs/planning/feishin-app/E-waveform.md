# E. Waveform feasibility and design

Ship an accurate standard seekbar and a deterministic generated waveform in MVP. Keep the first release Feishin-only. Revisit real waveform data and any separate service or credentials after the first release. Time mapping remains independent of the waveform provider.

## Feasibility

| Source | Feasibility and limits | Decision |
| --- | --- | --- |
| Feishin Remote API | No peaks, no transferable audio endpoint, no format/offset request for waveform data. Artwork proxy transfers only the current cover | Use current track identity, normalized duration and progress. A peaks command would be an upstream proposal |
| Navidrome / OpenSubsonic | No documented standard peaks endpoint or verified built-in Navidrome extension. `download` delivers original file when allowed. `stream` can transcode, and supported deployments may honor `format=raw`. Transcoding/offset discovery concerns media delivery, not peaks | Optional source for analysis with a separately configured, authenticated server. Check deployed capabilities via extensions/metadata and use TLS |
| Self-hosted peak analysis | Precompute or compute/cache on demand using a decoder and something like BBC audiowaveform. Deliver a versioned, compact envelope of duration, resolution and min/max or peak bins | Preferred real-data integration for frequent use. Costs are additional deployment, resource limits, identity/ACL design and ops. No proprietary service dependency for MVP |
| On-device decoding | Download an authenticated temporary file or stream bytes into a supported decoder. Use just_waveform or native MediaExtractor/MediaCodec spike. Accurate whole-track peaks usually require decoding across the full timeline even if PCM is never retained. Byte-range sampling can miss transients and seek points vary by codec/container. Compressed-file bytes do not encode a useful uniform amplitude envelope directly | Consider explicit foreground Wi-Fi-only opt-in after testing. Cancel on track change, network policy or backgrounding. Delete temp bytes on completion/failure and sweep orphaned files on startup. No decoder playback, audio focus, media scan or background analysis in MVP |

Bandwidth example at 240 s, decimal MB: 128 kbps is 3.84 MB, 320 kbps is 9.6 MB, and 1 Mbps is 30 MB, before overhead. A 512-bin envelope with two signed 16-bit amplitudes per bin is 2,048 bytes plus metadata. Transcoding can save bandwidth while increasing server CPU, changing amplitude or introducing encoder delay and duration drift. Use the original as the reference in tests. Prefer the peak service if repeated extraction taxes the phone or network. Benchmark MP3, FLAC, AAC and Opus, variable bitrate, gapless metadata, very long tracks and unsupported codecs. Record bytes, latency, peak memory, thermal/battery impact and cancel latency. [Navidrome compatibility](https://www.navidrome.org/docs/developers/subsonic-api/) · [OpenSubsonic download](https://opensubsonic.github.io/docs/endpoints/download/) · [Stream](https://opensubsonic.github.io/docs/endpoints/stream/) · [MediaExtractor](https://developer.android.com/reference/android/media/MediaExtractor) · [MediaCodec](https://developer.android.com/reference/android/media/MediaCodec) · [BBC audiowaveform](https://github.com/bbc/audiowaveform)

### Identity, credentials and caching for a later real-data source

Map the current Feishin backend ID/type to a separately authorized Navidrome origin. Navidrome's normalizer preserves the song ID for its song model. Verify it against the target's Subsonic metadata before enabling extraction, including more than one server with the same ID, migration/library rescans and the generic Subsonic adapter. Verify ID, duration within an agreed tolerance and available content identity such as stable version, file size/revision or server hash. Never match by title alone. Use TLS and an API key where supported or supported token/salt auth. Separate these credentials from desktop credentials and redact all request queries. Do not derive secrets from returned artwork URLs. Track-origin mapping and permission errors fail closed to fallback. [Feishin Navidrome normalization](https://github.com/jeffvli/feishin/blob/760b7829e3c2d9c3811ac46abc36e72f30f6d42d/src/shared/api/navidrome/navidrome-normalize.ts) · [OpenSubsonic auth](https://opensubsonic.github.io/docs/api-reference/)

Key peak entries by profile, backend origin, media ID, content version or validator, decode recipe and bin/algorithm version. Prefer strong validators. With weak metadata use a short TTL and verify duration on each read. Store only peaks plus minimum metadata, bound by LRU and bytes (initial proposed budget 20 MiB). Apply explicit purge on demand and when the last associated profile is removed. Coalesce requests for one key, validate finite bounded amplitudes and size, discard unfinished entries, and reject unauthorized peak access on the optional service. Treat oversize files or duration mismatch as an unavailable source.

## Proposed data flow

1. Playback reducer resolves a current occurrence and track identity. Seek UI receives verified duration plus a progress clock.
2. Standard style draws the slider. Generated style creates versioned, reproducible peaks by stable hash of backend identity and song ID, then deterministic pseudorandom envelope and fixed smoothing. Resample one canonical shape for screen width and density. Duplicate queue copies share shape. Explicit label in Settings and accessible description identify generated peaks as decorative.
3. In enhanced mode, Auto checks trusted cached peaks first, displays generated bars immediately, and requests a real source only if configured and allowed. Real-only mode displays a standard timeline with a source reason while waiting or unavailable. Generated mode makes zero audio requests. A verified result may crossfade only for the same track, profile and generation while not dragging. New library track, queue occurrence, profile switch or invalidation cancels prior display work. Immutable cache reuse for duplicates is allowed after identity checks.
4. Resample by preserving local maxima, limit draw count to available width, and precompute paths or per-bar geometry. Draw unplayed once and overlay played clipped by progress. Use a repaint signal plus bounded repaint area. Accessible Slider semantics and actions remain one logical control, with adjustable value, elapsed/total and optional step buttons. [Flutter CustomPainter](https://api.flutter.dev/flutter/rendering/CustomPainter-class.html)

### Seeking and reconciliation

- Normalize incoming/outgoing seconds and incoming duration ms into one internal Duration scale. Reject nonfinite values and clamp UI input to a known [0, duration] range. Use monotonic receipt time to project the latest anchor only while playing and fresh. Cap extrapolation after a missed update window, initially around 2 s subject to traces. Pause/stopped/disconnect freezes projection. Small corrections ease over a short interval, and large jumps reset immediately. Progress and visual waveform bars never affect seek math.
- On pointer-down capture profile, connection generation and latest queue occurrence. Finger owns preview and elapsed text. Desktop frames still update the underlying anchor without moving the handle. Cancel on new song, changed current unique ID, loss of freshness/disconnect or cancelled gesture. On release recheck the captured identity and send one absolute seek with fractional seconds. Tap-to-seek uses the same path. Keyboard/TalkBack step actions coalesce short bursts.
- Show pending commit briefly, then reconcile with an incoming position near the target and monotonic anchor. This is heuristic because frames have no seek ID, timestamp or track ID. A bounded settle window, initially 1–2 s subject to traces, returns to desktop progress on timeout or divergent authoritative state. No automatic resend. Seek cannot be made atomic against a desktop track change in flight. Test seeks near completion, repeated copies, rapid scrubs, desktop-issued seeks, paused seek and background resume.
- While a track has unknown duration or authority, show elapsed time where known and disable seeking. Accessible increment/decrement offer ±10 s, with a configurable step deferred to enhanced. Haptics on commit are optional and rate-limited. No haptics per bar.

### Settings preview and constraints

| Control | Proposed behavior |
| --- | --- |
| Style | Standard or Waveform. Source selector within Waveform shows Generated, Auto, Real as available |
| Bar geometry | Density presets, then advanced width/spacing and min/max heights. Prevent overlapping bars and inverted bounds. Start with 48–120 visible bars, 2–4 dp width, 1–4 dp gap and 4–44 dp height; adapt by layout |
| Shape and playhead | Rounded/square/pill bars and dot/line/none indicator. Always show visual and accessible progress |
| Colors | Theme roles, artwork accents or custom played/unplayed pair. Clamp effective colors to contrast constraints and preview on actual selected background type |
| Animation, smoothing, interaction | Animate correction and source changes where allowed. Height smoothing affects paint only. Keep tap/drag independent of motion. Optional haptic commit with system preference honored |
| Live preview | Stable sample metadata and generated peaks, visible source label, movable time, reset button. Playback is a local preview clock only and emits no remote command. Switch to standard and reduced motion immediately |

Accuracy and usability gates are in [G](G-roadmap.md). The included settings range and cache budgets are starting design values to confirm in the spike.
