# A. Research report

Research snapshot: 23 November 2026. The project is a FlutterAgentic Dart pub workspace pinned to Flutter 3.44.0 and Dart ^3.12. No runnable feishin-app workspace member exists. The imported reference client is useful evidence of one client design. It uses a broad ChangeNotifier, direct artwork plus a proxy fallback, saved profiles and an audio_service handler initialized at startup. The protocol, navigation and Android choices below were evaluated independently.

### Connection and wire contract

Enable Remote Control in Feishin desktop. The embedded default is `ws://HOST:4333/`, JSON messages over WebSocket, with commands as top-level fields and responses as `{event,data}`. With both credentials empty, initial state follows the upgrade. Otherwise send `authenticate` with string `header` equal to `Basic <base64(UTF-8 username:password)>` in a WebSocket frame. The server splits decoded credentials on colons. Reject colon-containing credentials in the form with an explanation. The HTTP UI and its credential mechanism are separate. There is no explicit auth success event or state request. An accepted `state` frame marks authentication success, even if the value is an empty object. Initial queue and queue-confirmation state follow. Desktop accent can arrive later. Auth expires at about 10 s and invalid credentials or auth expiry close with code 4004. Settings restarts can close with 4002. The desktop pings about every 10 s and terminates a connection that misses the next check. Use native WebSocket ping/pong support. [Server source](https://github.com/jeffvli/feishin/blob/760b7829e3c2d9c3811ac46abc36e72f30f6d42d/src/main/features/core/remote/index.ts#L166)

| Client event | Exact fields beyond `event` | Result |
| --- | --- | --- |
| `authenticate` | `header: string` | Initial snapshot or closure |
| `play`, `pause`, `next`, `previous` | None | Player commands, observe pushes |
| `shuffle`, `repeat` | None | Desktop toggle or cycle, never send an enum argument |
| `position`, `volume` | `position: number` seconds or `volume: number` percent | Position push is uncorrelated. Volume is clamped 0–100 and immediately broadcast by main process as well as observed from the renderer |
| `favorite`, `rating` | `id: string`, plus `favorite: bool` or `rating: number` | Only matching current song. Observe push. Backend support and range matter |
| `proxy` | None | Current-song artwork only, requester receives untagged base64 or generic error, no response if URL missing |
| `tracks-request`, `albums-request`, `playlists-request` | `requestId: string`, optional `limit: number`, `startIndex: number`, `searchTerm: string`. App sends integral paging values | Matching list response |
| `play-track`, `play-album`, `play-playlist` | `id: string`, optional `playType: Play`, `requestId: string` | Default `now`. Use `now`, `next`, `last` in MVP. Other enum values `shuffle`, `nextShuffle`, `lastShuffle`, `index`; wire calls have no index argument |
| `add-to-playlist` | `playlistId: string`, `songId: string`, optional `requestId: string` | Backend mutation and optional ack |
| `clear-queue` | Optional `requestId: string` | Optional ack and pushed queue |
| `queue-jump`, `remove-from-queue` | `uniqueId: string` | Snapshot confirmation only |
| `reorder-queue` | `uniqueId: string`, `targetUniqueId: string`, `edge: 'top' \| 'bottom'` | Relative placement, snapshot confirmation only |

| Server event | Exact shape of `data` |
| --- | --- |
| `state` | Partial object with optional `position` in seconds, `repeat`, `shuffle`, `song: QueueSong`, `status`, `volume` |
| `song` | Full `QueueSong` or null. Core consumed fields include `id`, `_uniqueId`, `_serverId`, `_serverType`, `name`, `artistName`, optional/nullable display fields such as `album`, `imageUrl`, `imageId`, `userFavorite`, `userRating`, and numeric `duration` in ms. Other metadata can include year, track/disc, genre, bitrate and format. Use field-level validation |
| `playback`, `repeat`, `shuffle`, `position`, `volume` | `paused/playing/stopped`, `all/none/one`, bool, numeric seconds, numeric percent respectively |
| `favorite`, `rating` | `{id: string, favorite: bool}` or `{id: string, rating: number}` |
| `queue-state` | `{currentUniqueId: string?, items: RemoteQueueItem[]}`, where the current ID is nullable and each item has the track-list fields plus `uniqueId: string` |
| `tracks-response`, `albums-response`, `playlists-response` | `{requestId: string, items: T[], hasMore: bool}` |
| `confirm-queue-changes-setting`, `accent-color` | bool with safe desktop startup default true, or `{dark: string, light: string}` |
| `proxy`, `error`, `operation-ack` | Base64 string, uncorrelated error string, or `{requestId: string, error?: string}` |

List field inventory: tracks have string `id`, `name`, `artistName`, nullable strings `album`, `imageUrl`, numeric `duration`. Albums have string `id`, `name`, `albumArtistName`, nullable `imageUrl: string`, `duration: number`, `releaseYear: number`, `songCount: number`. Playlists have string `id`, `name`, and nullable `imageUrl: string`, `duration: number`, `songCount: number`. Track durations originate from normalized backend data. Treat absent or nonpositive duration as unknown. The bundle also catalogs excluded desktop events. The app's protocol adapter consumes only its supported subset and safely ignores other event names. ### Schema versus implementation

| Finding and confidence | Consequence and verification |
| --- | --- |
| **High**. Enums and core shapes agree. Bundled schemas are strict with partial song fields. Runtime parses JSON and switches on event without applying those schemas. List offsets are TypeScript numbers, restricted to integers in the bundle | Use strict outbound commands and tolerant inbound parsing. Fixture absent, null, extra and invalid fields. Discard unsafe field values atomically for authoritative queue edits |
| **High**. Main process uses a shared request map keyed by request ID, with a roughly 15 s uncorrelated timeout. Library failures and no connected music backend return the same empty final page as legitimate emptiness | Use globally unique IDs across clients and connections. Expire requests independently. Provide retry and desktop-library guidance for ambiguous emptiness |
| **High**. Album/playlist play handlers issue ack without awaiting async fetch. Track ack follows track lookup/dispatch, playlist-add awaits backend mutation. Ack and queue push can arrive in either order | Distinguish acknowledged from reflected. Match expected outcomes in the authoritative queue or show an uncertain result. Never replay a timed-out mutation |
| **High**. Lists default to 30, offset 0, and ask backend for name ascending. `hasMore` usually means page filled, so a final empty page is normal. Plain Subsonic empty track query mixes random batches with perpetual `hasMore`. Search and pagination vary by backend. Subsonic playlist filtering is desktop-side | Use per-category query and offset, raw item count for paging, dedupe rendered library IDs, stop on repeated no progress, and label generic Subsonic track sampling where known. Capture representative paging traces through Feishin Remote with desktop-configured backends |
| **High**. Position is seconds. Track durations are ms. Remote progress is forwarded from playback engines, with nominal 250 ms polling in MPV and web-player timing that varies during transitions. No timestamp, occurrence ID or seek ack in position messages | Normalize units at the boundary. Record real cadence, pause behavior, and seek latency on both engines. Use bounded interpolation and conservative reconciliation |
| **High**. Song pushes are gated on library song ID changes. The same track repeated as a different queue entry can show up only through queue state, debounced around 250 ms | Reset drag/pending seek on occurrence change and use queue ID for identity. No atomic track-scoped seek is available. Test repeated copies of the same track and same-ID server-switch fixtures |
| **High**. Artwork URL may be returned as-is or generated using the backend remote URL. Some source URLs include credential-derived query values. Desktop proxy captures only the current image and returns no identity or MIME. The imported Dart client uses it | Prefer direct artwork with strict origin handling and placeholders. Use a placeholder for missing images and keep playback controls independent of image loading |
| **Medium**. Favorite/rating require current ID and supported backend mutation. Playlist editability is absent from remote list payload. Navidrome delegates rating to the Subsonic controller. Jellyfin has no corresponding rating implementation in the reviewed controllers. Backend, client build and account privileges affect results | Test edit rights and 0–5 rating semantics per supported backend. Show rating only on confirmed combinations. Explain rejection by backend in playlist picker |
| **Medium**. Queue list lacks revision/region metadata. Clear resets queue arrays and current index. Reorder behavior at priority boundary differs between the tag and development | Validate jump, active removal, clear playback outcome, shuffle, and concurrent desktop/phone edits on the compatibility matrix. Label uncertain outcomes and reflect the next snapshot |

Protocol gaps: album/playlist membership, playlist ownership or creation, artist browse, aggregate search, queue revisions, request cancellation, capability/version negotiation, audio transfer and waveform peaks have no corresponding Remote API contract. Transport open does not prove a functioning desktop renderer or connected backend.

| Reactive state | [flutter_bloc 9.1.1](https://pub.dev/packages/flutter_bloc) (2025-05) offers event/state separation, selectors and local examples. | Material 3, dynamic palette | Flutter SDK Material components and `ColorScheme` supply app roles. [Android dynamic colors](https://developer.android.com/develop/ui/views/theming/dynamic-colors) |
| Artwork palette | [palette_generator 0.3.3+7](https://pub.dev/packages/palette_generator) is discontinued. | Waveform | [waveform_flutter 1.2.0](https://pub.dev/packages/waveform_flutter) (2024-12) is visual-only oriented; [audio_waveforms 2.0.2](https://pub.dev/packages/audio_waveforms) (2026-01) has native extraction but couples much of its API to recording/player controllers. [just_waveform 0.0.7](https://pub.dev/packages/just_waveform) (2025-03) is a narrow local-file extraction candidate with modest release cadence. | Preferences and secrets | [shared_preferences 2.5.6](https://pub.dev/packages/shared_preferences) (2026-10, Flutter ≥3.41) offers async access and Android DataStore backend; use for small non-secret settings. SQLite would add query/migration cost with little benefit for this state. [flutter_secure_storage 11.2.0](https://pub.dev/packages/flutter_secure_storage) (2026-09) offers Android-backed secret storage. Verify upgrade, key loss and backup policy before use |
| Image cache | [cached_network_image 4.0.7](https://pub.dev/packages/cached_network_image) (2026-11, Flutter ≥3.44) provides placeholders, cache and resize integration. Prefer cache primitives behind one artwork repository with opaque keys and sensitive-source disk restrictions; validate cache metadata before choosing the plugin path |
| Media and background | [audio_service 0.18.19](https://pub.dev/packages/audio_service) (2026-06) is documented and present in the reference prototype, but its background audio service assumptions require review. Native Media3 offers an explicit remote-device Player adapter. [workmanager](https://pub.dev/packages/workmanager) suits finite deferrable jobs, not a live socket. No local playback stack or audio focus is needed |
| Testing | SDK unit/widget/integration_test, accessibility guideline API, DevTools timeline and Android profiler cover core needs. BLoC tests and a fake WebSocket improve determinism. An emulator alone cannot settle headset routing, battery, texture performance or OS media policy |

## Navidrome and waveform findings

The first release uses Feishin Remote for playback and catalog operations. The following research informs a later real-waveform decision.

The inspected Feishin protocol has no peaks or audio stream request. Navidrome's published compatibility list and OpenSubsonic endpoint/extension catalog document original downloads and streaming, API discovery and transcoding features. Neither documents a waveform endpoint. Navidrome plugins are versioned integration surfaces and provide no verified built-in waveform facility here. A custom peak service remains possible. Confidence is high for the documented contract, medium for deployment-specific plugins, original-file permissions and identifiers across versions and migrations. In a spike, compare the same media on the active Feishin backend and configured Navidrome instance via authenticated metadata and validate duration/codec, then measure representative extraction. [Navidrome compatibility](https://www.navidrome.org/docs/developers/subsonic-api/) · [Plugins](https://www.navidrome.org/docs/usage/features/plugins/) · [OpenSubsonic extensions and endpoints](https://opensubsonic.github.io/docs/endpoints/) · [Waveform report](E-waveform.md)

## Android findings

| Capability | Feasibility and plan |
| --- | --- |
| Foreground app | Direct WebSocket control and in-app remote volume. Request local-network permission at the point of connecting where required. Android 17 enforces `ACCESS_LOCAL_NETWORK` for target SDK 37+, while lower target levels presently receive implicit access with INTERNET. Handle denial/revocation and validate on the launch target. [Local network permission](https://developer.android.com/privacy-and-security/local-network-permission) |
| Media session | Enhanced release experiment with native Media3 Player backed by confirmed desktop metadata, explicit remote playback/device state (`SimpleBasePlayer` with `DeviceInfo.PLAYBACK_TYPE_REMOTE`) and the same command authority. CastPlayer demonstrates remote representation but Feishin transport is independent. The reference audio_service example is a prototype candidate. Do not create a local player, play silent audio or claim local audio focus. [Player interface](https://developer.android.com/media/media3/session/player) · [Remote playback type](https://developer.android.com/reference/kotlin/androidx/media3/common/DeviceInfo.html) · [MediaSession](https://developer.android.com/media/media3/session/control-playback) |
| System media, lock screen, headset | MediaSession can expose metadata and commands to system surfaces and media-button dispatch. Android version, OEM and active-session arbitration determine visibility/ownership. System actions only while fresh and connected, clear/deactivate on loss. Do not pair with or intercept Bluetooth devices directly. Verify competing music session, pause, headset, lock screen and process death. [Media controls](https://developer.android.com/media/implement/surfaces/mobile) |
| Background | MVP connects while in use and restores fresh state on resume. Android background start limits, Doze and OEM suspension make permanent connectivity unreliable. Explore opt-in, visibly stoppable active remote sessions only after validating foreground service eligibility and required permissions. `connectedDevice` includes network interactions and has permission prerequisites, with Play policy eligibility still to establish. Treat persistent media integration as conditional. [FGS types](https://developer.android.com/develop/background-work/services/fgs/service-types) · [Background restriction](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start) · [Doze](https://developer.android.com/training/monitoring-device-state/doze-standby) |
| Home widget and Wear OS | Defer. A native Android widget or [home_widget](https://pub.dev/packages/home_widget) can show timestamped state and open the app. Remote widget commands require fresh bounded connectivity and failure UI. Wear OS needs session compatibility tests or a phone companion channel with connection and session checks. [Widgets](https://developer.android.com/develop/ui/views/appwidgets/overview) · [Wear OS media](https://developer.android.com/media/implement/surfaces/wear-os) |
| Android Auto | Defer pending a demonstrated use case and category/policy review. A controller-only desktop path does not deliver audio to the car. Media surfaces typically need a browseable service and conforming playback experience. [Android for Cars](https://developer.android.com/media/implement/surfaces/cars) |
