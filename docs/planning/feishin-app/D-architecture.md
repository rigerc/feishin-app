# D. Technical architecture proposal

Propose a Flutter app within the existing workspace, with feature-facing BLoCs, a single active remote session, a typed Feishin protocol adapter, and bounded artwork and waveform providers. Android features enter through adapter interfaces. The Android-only product direction is confirmed. This design and architecture proposal awaits separate implementation approval. Existing workspace conventions inform the recommendation after the validated flows and technical constraints. No workspace layout change is implied by this document. [Workspace architecture](../../reference/architecture.md) · [Candidate research](A-research.md) · [UX](C-ux.md)

## Responsibilities and dependencies

```text
Material 3 shell, screens, accessible controls
    → Feature presentation state and explicit user intents
        → Use cases / domain interfaces
            ← Desktop adapter → WebSocket → Feishin desktop → active library backend
            ← Profile metadata store and secure secret store
            ← Artwork service → eligible image origins + cache + palette worker
            ← Waveform data → generated locally in MVP, real peaks pending later review
            ← Android bridge → operating system media surfaces, if enabled

Authoritative frames → desktop session reducer → read-only typed streams
    → Library, playback and queue presentation slices
    → Position clock → seekbar/mini-player time, only when visible
    → Android projection, only while connected and fresh
```

| Boundary | Responsibilities |
| --- | --- |
| Connection profiles | Endpoint validation, secret references, lifecycle intent and connection state. One socket owner per active profile |
| Desktop session | Immutable playback/queue read model and capability hints. Protocol parse/serialize, operation lifecycle, command ordering, epochs, deadlines, push reduction. Owns the network clock anchor. Session is app-scoped across routes |
| Playback and queue | Render selected state slices. Track occurrence, current status and queue anchor validation. Intents call typed use cases. Transient scrubbing and drag preview stay local; pending operations remain explicitly separate from snapshots |
| Catalog | Independent per-category query/paging state, read retries and stale-request protection. Maps current desktop catalog only and keeps ephemeral recent views; no offline music database |
| Preferences & presentation | Global settings validation and migrations, persisted start screen, local-only live preview, device palette and motion signals, routing and responsive composition |
| Media resources | Validated artwork fetch/decode/cache, palette computation, generated or optional real peaks, identity-keyed async result guards |
| Android | Runtime permission and platform signals in MVP. Separate opt-in presentation/control bridge after validation. Native callbacks go through the same command and authorization checks as Flutter UI |

Map wire DTOs to typed domain entities and use repository interfaces with typed failure results. Keep Flutter, WebSocket and persistence outside the domain. Use workspace DI for composition, scope BLoCs to their navigation lifetimes and keep app-specific behavior in the app layer. Avoid creating two competing sources of desktop state. Use BLoC selectors and isolated repaint signals and keep frame-rate updates out of business state.

## Decisions and alternatives

- **State and composition.** BLoC and immutable reducer align with workspace conventions and keep command/event ordering visible. The imported ChangeNotifier client is useful for exploratory captures. Riverpod can manage lifetimes and async providers but would introduce a second workspace convention. Treat high-frequency painting as a Flutter render concern.
- **Routing.** go_router for session-driven shell and full-screen player routes, with saved branch state, first-launch onboarding, and a persisted Start screen preference (Now Playing default or Library) for fresh launches. A small imperative Navigator stack is credible if nested predictive back or tablet restoration proves simpler. The current workspace lock resolves go_router 17.2.3, so validate the needed APIs with that version first. Validate origin-aware Back, system transitions and screen-reader focus before committing.
- **Transport.** web_socket_channel I/O adapter with no extra reconnect package. Its closure and readiness channels permit explicit decisions. Dart WebSocket directly is viable for Android-only delivery. Android is the only supported product platform. A workspace preview can use mock state for design review.
- **Storage.** SharedPreferencesAsync for small versioned configuration, Flutter secure storage for secret material. Use staged replacement of credentials and a reference pointer, with cleanup of stale keys after writes or deletes and recovery on backup/key loss. Preserve nonsecret preferences across migration. Consider transactional storage when multiple live sessions or durable catalog features add a concrete need.
- **Media.** Narrow fetch/cache/palette and peak-provider interfaces. Start with SDK image decoding and a checked cache implementation, SDK painting and M3 Slider semantics. Native palette extraction is an alternative if Dart sampling has high startup or isolate cost. A waveform playback package would unnecessarily bind transport to a player controller. The workspace already resolves material_color_utilities 0.13.0. Use an SDK-compatible release. Separate peak service only if enabled by user.
- **Theme.** Keep config-driven workspace tokens for typography, density, radius and static schemes. The shared theme builder currently derives its ColorScheme from configuration. Feed device roles through the existing override model when feasible and validate every component-state role. An explicitly approved scheme-input extension is a fallback if the builder cannot preserve the full device scheme. Player atmosphere remains a scoped painter.
- **Android.** Platform bridge is behind an app-owned interface. For enhanced MediaSession, prototype a lightweight Media3 remote Player with supported commands only. Avoid two sockets and duplicate state reducers between Flutter and Android. If a compliant background lifecycle is later approved, one process-owned session must outlive the Activity, behind an explicit owner boundary. Platform-owned transport is an alternative only if the Flutter isolate cannot reliably remain available. A simpler open-app control notification is a separate opt-in experiment.
- **Cost and ownership.** Android app has no mandatory hosted infrastructure or application account. Desktop and library are user-operated. TLS reverse proxy and optional peak service have deployment and maintenance cost. Keep diagnostic export local and opt-in.

## Session and data flow

1. Validate endpoint and permission, create incrementing connection generation, attach listeners, then open. Send socket auth if configured. Separate transport, auth, first snapshot, ready and retry states. A valid empty `state` can prove auth but does not prove a usable catalogue. Buffer early recognized pushes during handshake. Require a queue snapshot before enabling queue editing.
2. Observe close/error or freshness failures. Use client ping/deadline behavior compatible with desktop pings, bound connect/auth deadlines and jitter capped exponential backoff, initially 1–30 s, only while the app actively needs a connection. Treat 4002 as retryable and 4004 as an edit-credentials state. Manual disconnect cancels retry. Retire old generation, fail pending requests, block writes and retain a timestamped read-only snapshot only within the same profile. For background MVP, stop painting, stop retries and close the socket when genuinely backgrounded. Resume by restoring connection and fresh snapshots. Transient app overlays receive a short grace so they do not cause churn.
3. For reads and ackable operations generate random globally unique IDs with expected response, target/profile, generation, category/filter and deadline. Store bounded pending entries, ignore out-of-scope responses and release on close or expiry. For listing, a read retry uses a new ID and same cursor generation if still current. Cursor tracks raw count, result list dedupes by ID, and no-progress loops stop. Backend changes invalidate results once evidenced; cross-backend identifiers must not collide in caches.
4. Decode finite values, lengths, enum shapes and trusted artwork locators. Tolerate additive fields and unknown message types. Keep invalid rows or queue snapshots from driving commands. For an invalid queue snapshot, mark queue stale and keep earlier state read-only until fresh. Treat raw `error` as a sanitized, uncorrelated diagnostic, never attribute it to the newest request. Use targeted reconnection if snapshot freshness cannot be recovered. A version field is not available, so capabilities are evidence-based, conservative, and must not be inferred from silence.
5. Queue intents capture latest known current occurrence and target IDs. Encode placement before/after mapped to top/bottom. Recheck source, target and relative context before release. Serialize queue writes while pending and present tentative changes distinctly. Desktop snapshots always replace local base, even if they disagree. Prefer verifying expected adjacency/absence/current ID with fresh snapshots; otherwise reconcile to desktop and report uncertainty. Ack arrival can be before or after the expected snapshot. The protocol has no revision, idempotency key or atomic precondition.
6. Position, image and peaks depend on different identities. Position gestures use connection generation and queue occurrence. Peaks may share across duplicate occurrences when track/content identity matches. Artwork and palette use artwork revision plus display generation. Timestamp and isolate completion are ownership checks at the UI boundary. High-frequency anchor updates avoid rebuilding entire routes. ## Security and failure policy

- Default new profiles to trusted LAN with a disclosure before connecting that Basic credentials and control frames use cleartext. Offer WSS with system-trusted certificates and hostname verification, including on a user-managed proxy. Retain the chosen transport per profile and treat a WSS failure as a connection error. Android network-security and local-network permission behavior are target-dependent and require device validation. Check actual proxy root/path, upgrade, idle timeout and auth framing. [Android network security](https://developer.android.com/privacy-and-security/security-config) · [Local network permission](https://developer.android.com/privacy-and-security/local-network-permission)
- Strip credentials and full URLs from logs, crash breadcrumbs, cache indexes, analytics and exports. Redact server-supplied free-form error text by mapping to safe categories. Store Feishin credentials in Android-backed secure storage. If a later real-waveform integration is approved, keep its credentials separate. Exclude keys/secret references from backup where appropriate and recover by asking for credentials upon key loss. Never attach the Feishin auth header to HTTP image requests.
- Verify image scheme and explicit trust for library artwork origin, prefer HTTPS, reject unexpected redirects and URL userinfo, and apply byte/dimension/time caps. Use opaque cache keys and omit URL-bearing metadata. URLs containing auth-derived query values stay ephemeral and only go to the configured image origin. Never export or forward them. Use eligible artwork URLs provided by Feishin. Render a placeholder and background fallback for unreachable or rejected images while the control session continues independently.
- Limit frame size, queue decode load, image transfers and pending requests. Large authoritative snapshots are handled as a bounded workload or surfaced as unsupported with a clear reason. User-visible failures distinguish invalid input, denied local access, auth, transport, stale session, unsupported backend behavior, uncertain command, decode and timeout where identifiable.
- No command replay after timeout or reconnect. Temporary state never authorizes actions across profile or connection changes. Diagnostics include sanitized state transitions, close category, queue age, timing/size counters and app version.

## Nonfunctional targets and verification

Target 60 FPS on the agreed baseline Android device. On profile builds, use 16.7 ms frame budget and a proposed target of at least 95% UI and raster frames under budget for scrolling, dragging and palette transitions after warmup. Review cold artwork and rapid-skip traces separately, with no recurring main-isolate decode/quantization or unbounded memory growth. Start with bounded decoded thumbnails, conservative 50 MiB disk artwork budget subject to tests and two simultaneous cover downloads, enough to prefetch one viewport. Use a 10k-track dataset, a queue with duplicates and measured large snapshots. Disable render clocks when unseen and compare battery against idle app behavior. Reduce visuals before degrading input. [Flutter DevTools](https://docs.flutter.dev/tools/devtools/performance)

Test reducer and codec fixtures, retry/clock behavior with fake time, WebSocket handshake and fault injection, UI states and semantics in widget tests, screenshots in light/dark at adapted widths and integration runs against Feishin desktop. Use hardware for lifecycle, TalkBack, GPU and battery. Workspace analysis and app test suites are release gates. Full coverage and ownership appear in [G](G-roadmap.md).
